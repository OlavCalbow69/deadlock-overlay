# Hero detection and Vindicta's sniper

The Camera Focus tab shows the local hero automatically. **Hero / abilities** opens the detected hero's details and links to the separate **Vindicta Ultimate** tab. That tab has independent camera-focus enablement, speed, target bone, hold button, Visible only, free movement, focus visuals, acquisition-area mode/radius and per-mode area drawings. Assassinate always targets enemy players only, including in replay, after copying/resetting controls, with old saved settings and while scoped with the separate profile disabled. Its Auto Click profile also excludes minions/orbs/allies. Its FOV control changes the acquisition area, not the game's view FOV.

**Profile options → Use separate ultimate profile** enables automatic switching while validated Vindicta Assassinate scope data is active. Unscoping, changing hero or losing valid ability data restores every regular control. Disabling Camera focus on the ultimate tab stops steering while scoped without disabling regular focus. Opening a settings tab does not select its runtime profile. Selections and queued mouse corrections are cleared on profile/scope transitions.

Existing installations seed the ultimate profile from their current regular controls and preserve the previous `sniper_focus_speed` and `sniper_speed_override` values. Subsequent saves use independent `vindicta_ult_*` keys in settings.ini. **Copy regular controls** and **Reset ultimate controls** affect only the ultimate profile and keep its fixed enemy-player restriction. Health-tab visuals always exclude teammates; the ultimate's Visible only applies to its own targeting and focus guides.

Assassinate is hitscan in the inspected build 6766 server code. Projectile travel prediction is therefore always off while validated Assassinate scope is active, including when the separate profile is disabled. Automatic compensation for a motion sample's age remains on, without projectile travel or shooter-velocity inheritance; Fixed bone, V1, V2 and Adaptive use timestamped motion for this. Normal projectile-prediction settings are preserved for unscoped play. The ultimate tab has no Prediction panel or prediction controls. See [the reverse-engineering report](VINDICTA_ASSASSINATE_6766.md) for the evidence and limits.

Names come from the installed game's English hero localization and its live hero table. They are not inferred from a selected GUI option or the primary weapon. `Snapshot::hero` carries the current ID, name, internal token and sniper state for future hero features. Only Vindicta currently has an ability-specific focus profile.

Build 6759's `CCitadelHeroComponent::GetHeroData` at client RVA `0x767600` looks up spawned/loading/no-spawn IDs in the hero table: count `0x36EDED8`, data pointer `0x36EDEE0`. The local pawn's component is at `0x1620`; the spawned ID is component `+0x20`. The record's `CitadelHeroData_t::m_HeroID` must match. Record `+0x30`/`+0x38` contains sort/search localization tokens; Vindicta is ID 3, `hero_hornet`.

The reader resolves `CCitadel_Ability_Hornet_Snipe` from the local pawn's actual ability vector (`0x1440 + 0x68`), validates its full entity handle, and reads `m_flScopeStartTime` at `0x1FE4`. Scope code at `0xFB5DB0` sets the timer; unscope code at `0xFD1FF0` clears it. A positive finite timer activates the override. Merely holding aim, owning the ultimate or having it selected does not activate it.

Hero metadata and ability identity are cached, with bounded caches. Switching pawn/hero or changing the ability vector invalidates the relevant cache. Failed or unstable reads publish no active override. Runtime diagnostics include the detected hero and scope state in `session.json`; `camera.json` records the active profile (`regular` or `vindicta_ult`), scope gate and effective targeting, input and drawing controls. Extra target and hitbox sampling follows the active profile.

# Aspect overrides and projection

`r_aspectratio` can alter the field of view even when the window resolution stays the same. Build 6753's cached `ScreenTransform` matrix uses the legacy view's aspect override, while the final renderer uses the compact render view's aspect. With `r_aspectratio 2.3` on a 2560 x 1440 window, the cached matrix reported 2.3 but the actual render matrix reported 1.777778. Applying the cached matrix stretched overlay positions vertically.

The reader uses the renderer's completed world-to-clip matrix directly: build 6759's `CViewRender` at client `0x3689A70`, matrix at object `+0x298`. Static initializer `0x092810` identifies this object; `0x2195400` builds the final matrix. Its vtable and binary hash are checked. The view's update flag and live FOV/aspect checks reject incomplete camera updates. There is no fixed game FOV, config-file rewrite or guessed FOV multiplier. Skeletons, markers, visibility camera origin and camera focus share this final projection, including normal aim and sniper zoom.

The Connection tab and Hero / abilities popup show the live render FOV and aspect. These are different from the camera-focus acquisition area's **Show FOV** control.

Skeletons omit all head/head-end and neck segments. Both shoulders connect to the highest joint of the remaining drawn spine, even when their original parent was the neck or a lower spine joint. The chest-to-pelvis spine, arms and legs remain. The menu preview uses the same connections as the live skeleton.

Bone anchors use a single model rig. Ordinary models keep their unprefixed names. If those head bones are absent, the reader accepts a unique prefixed rig with connected head, torso and pelvis joints. Baba's model uses `baba_head`, `baba_head_end`, `baba_spine_2` and `baba_pelvis`; its unprefixed pelvis belongs to a separate mount rig. Skeleton drawing normalizes only the selected rig's names, while hitbox binding retains the original names. The rig is resolved once per cached model, without hardcoded bone indices or hero IDs.

Build 6769's Rat King and Solomon models have 132 and 152 mesh records respectively, including body groups and LODs. The hitbox loader accepts up to 256 records; mesh count is independent of the 64-bit body-group mask. The former 64-record bound rejected these entire models before reading their valid hitboxes, leaving Free movement V2 without geometry even though bones and player enumeration worked. Live reads after the fix recovered 21 active Rat King hitboxes and 23 Solomon hitboxes. Set/box limits, shape validation, name binding, active-set/mask selection and concurrent-change checks remain in place.

Failed name or parent-table reads are retried rather than cached as incomplete metadata. `--probe` and `--diagnostics` report each player's model, rig prefix and anchor, plus `skipped_players` with explicit exclusion reasons. The Connection player count represents successfully read, alive remote players; it excludes the local player and can decrease when players die, become dormant or have no current pawn.
